# Database standards
- Default PostgreSQL with EF Core/Npgsql Code First. Inspect provider/version, naming conventions, DbContext, mappings, migration history and deployment topology. Follow existing naming, key, tenancy, audit and soft-delete conventions.
- Coordinate domain model and schema: nullability, constraints, foreign keys, delete behavior, precision, time zones, unique indexes and query patterns. Use parameterized queries; avoid unbounded reads and N+1. Index based on actual predicates and measured plans, not speculation.
- Generate migrations using repository-specific EF commands and correct startup/context/project. Review migration and snapshot, generated SQL, existing-row compatibility, locks, data backfill, transaction behavior and rollback/forward recovery. Keep migrations deterministic and source-controlled. Never rewrite already deployed migrations without explicit coordination.
- Prefer expand/backfill/contract for risky schema changes; separate destructive cleanup and obtain explicit approval. Do not run database update against shared/production targets without explicit authorization and verified target. Use disposable local/test database for testing with consent and safe credentials.
- Report migration names, SQL review, data risks, checks and unapplied status. If EF tooling or PostgreSQL unavailable, state limitation; do not claim migration generated if hand-written or unverified.
