# Backend standards
- Default C#/.NET ASP.NET Core, Clean Architecture, DDD, CQRS with MediatR, EF Core Code First, REST. Inspect target frameworks, package versions and existing feature structure. Keep domain independent of infrastructure and transport; Application depends on Domain; Infrastructure implements ports; API composes dependencies. Respect established variations.
- Domain: model aggregates, value objects and invariants where meaningful; avoid anemic or overengineered models. Preserve audit, soft delete, tenancy, domain events and concurrency conventions if present. Keep business rules out of controllers and React.
- Application: distinct commands/queries, handlers, DTOs and cancellation tokens. Validation and mapping are project-dependent; reuse existing pipelines and libraries. Coordinate transaction boundaries, idempotency, errors and side effects. Avoid returning tracked entities or leaking persistence details.
- Infrastructure: repositories implement existing interfaces; use async EF operations, projections, pagination, no tracking for read paths where appropriate; avoid N+1 and unbounded queries. Register DI lifetimes correctly. Do not introduce generic repositories or extra layers merely for style.
- REST: preserve routing, status codes, response envelopes, paging/filtering, error format, OpenAPI and versioning. Validate inputs and authorize every protected operation. Controllers should delegate to application logic. File uploads use bounded sizes and safe storage with authorization.
- Logging: prefer existing Serilog structured logging; do not add duplicate providers or log credentials/personal data. Use correlation IDs and appropriate levels.
- Caching: Redis or in-memory according to project, with explicit TTL, invalidation, tenant/user isolation and failure behavior. Messaging is project-dependent; preserve delivery semantics, retries and idempotency; outbox only when warranted.
- Feature checklist: trace nearest feature; domain -> application -> infrastructure/EF -> migration -> API/DI -> contracts -> tests/docs. Verify xUnit and dotnet build using actual solution paths. Do not upgrade packages or alter auth stack without scope.
