# Frontend standards
- Default Next.js App Router, React, strict TypeScript, Atomic Design, Tailwind CSS, Redux Toolkit/RTK Query and next-intl. Inspect actual Next/React versions, package manager, tsconfig, local component hierarchy and UI/form libraries before edits.
- Server-first: prefer Server Components for public/read-heavy rendering and server-only fetching where appropriate; use client components only for interactivity, hooks or browser APIs. SSR/ISR/cache behavior is version- and route-dependent. Specify appropriate freshness and invalidation, avoid caching private data across users. Preserve loading/error/not-found states and hydration correctness.
- Atomic Design: reuse atoms, molecules, organisms, templates and existing feature boundaries; keep business logic out of presentation. Avoid premature abstractions and unnecessary prop drilling. Maintain clear server/client boundaries; do not expose secrets via NEXT_PUBLIC or client bundles.
- State: use local state for local interactions; Redux Toolkit for genuinely shared client state; RTK Query for client API lifecycle where established. Reuse base API, typed endpoints, tag invalidation and store setup. Avoid duplicating server data in slices, cross-request singleton stores, stale caches and optimistic updates without rollback.
- Styling: Tailwind and existing semantic tokens; respect project-specific theme colors, fonts, spacing, dark mode, dynamic settings and portal styles. No hardcoded configurable values. UI and form libraries are project-dependent; do not replace them unasked. Accessible semantic controls, keyboard/focus, contrast, labels and reduced motion.
- Localization: next-intl by default; use existing message keys, locale routing and formatting. Support RTL/LTR where applicable, logical CSS, long text, locale-aware dates/numbers. No forced brand-specific aesthetic.
- Verify responsive layouts, all relevant interaction/data states, actual browser rendering, type check, lint, build and existing test runner. Use installed React/Next/design skills when available. Preserve API contracts and user changes.
